How to use the Bondhon Management & Auditing System

This guide shows the steps for your role{% if roles %} ({{ roles|join:", " }}){% endif %}. Click a heading to open or close a section. Everything you do is recorded in an audit trail, so enter information carefully and give a reason whenever the system asks for one.

Admin

Controls users, settings and approvals. Can void entries and re-open a closed audit.

Treasurer

Records deposits and expenses, verifies member payments, sends SMS. Expenses need admin approval.

Auditor

Reads everything, runs audit checks, records findings and signs off an audit. Cannot change the books.

Member

Sees own statement and receipts, deposits money and receives notifications.

{# ------------------------------------------------------------------ #} {% if is_admin %}
  1. Fix the members' mobile numbers. Go to Members → CSV to download the list, correct the phone_number column in Excel (keep the id column), then use Import / update. Numbers like 01712345678 are valid. Without valid numbers no SMS can be sent.
  2. Fill in Settings. Open Settings: society name and address, the receipt prefix, the default fund head, and the bKash / Nagad / Rocket numbers and bank details that members will see when they deposit money.
  3. Check the fund heads. The same page lists the fund / expense heads. Add any missing ones.
  4. Create the people who will work in the system. Open Users & roles → New user. Choose the roles (Treasurer, Auditor...). A temporary password is shown once - copy it and give it to the person.
  5. Give members their portal login. Open a member's page and press Create login. Tick “Send login details by SMS” if SMS is already live. The member must change the password on first sign-in.
  6. Set up SMS. The system starts in test mode: messages are recorded but not sent. When your SMS provider details are in the server's .env file, change SMS backend in Settings to “HTTP provider”. Then send a message to yourself from Compose to test.
  7. Contribution plans. Under Contribution plans each plan has an amount per share. Adding a plan raises every member's expected amount.
{% endif %} {# ------------------------------------------------------------------ #} {% if can_finance %}

Record a deposit

  1. Press Deposit (top of the Dashboard or the Deposits page).
  2. Choose the date, member, amount, fund head and how it was paid. For bKash/Nagad/bank, write the transaction ID in reference.
  3. Press Record deposit. A numbered receipt is created and the member receives an SMS automatically. Use Print receipt to give a paper copy.

Entered something wrong?

Open the deposit and press Edit for a small correction (changes are logged and visible to auditors). To cancel a deposit completely, ask an Admin to void it with a reason - deposits are never deleted, and a voided deposit is removed from all totals.

Record an expense

  1. Press New expense.
  2. Fill in the description, head, amount and who paid. Add the voucher number and attach a photo or PDF of the bill - auditors check for this.
  3. {% if is_admin %}As Admin your expense is approved immediately.{% else %}Your expense goes to the Admin for approval and counts in the books only after it is approved.{% endif %}

Verify a member's online payment

  1. Open Member payments and choose a Pending one.
  2. Check the transaction ID and amount in your own bKash / Nagad / Rocket / bank statement.
  3. If it matches press Confirm payment (this creates the deposit and sends the receipt SMS). If not, write a reason and press Reject - the member is told why.

Send messages

Open Compose. Choose who gets it (selected members, everyone, or only members with dues), pick a template or write your own, and press Send. Placeholders such as {member_name} and {due} are filled in for each person; the preview shows the result and the number of SMS parts. The Outbox shows what was sent, failed or skipped.

Chase dues

Open Dues to see who owes what. Press SMS reminder to all to send the reminder template to every member with a due.

Reports

Reports has the monthly ledger, fund-wise summary, collection by plan and dues. Lists can be filtered, exported to CSV or printed.

{% endif %} {# ------------------------------------------------------------------ #} {% if is_admin %}

Approve expenses

The Dashboard shows “expenses waiting for approval”. Open each one, compare it with the attached bill, then Approve or Reject (with a reason).

Void a wrong entry

Open the deposit or expense, choose Void, write the reason and confirm. The record stays visible for the auditors.

Users & roles

Add or disable users, change roles and reset passwords at Users & roles. A reset password is shown once - give it to the person. You cannot remove your own Admin role.

Re-open a closed audit

After an auditor signs off, records in that period are locked. If a late bill must be added, open the audit → Sign-off → Re-open, with a reason. It is recorded in the audit trail, and the auditor should close it again afterwards.

{% endif %} {# ------------------------------------------------------------------ #} {% if can_audit %}

Start at Audit overview. It shows whether the audit trail is intact and the most serious exceptions found by the automatic tests.

Conduct an audit step by step

  1. Create the engagement. New audit → give it a title, the period (for example 1 Jan – 31 Dec) and the scope.
  2. Run the analytics. Open the Analytics tab. Each test shows its exceptions; press Details to see the records.
  3. Raise findings. Press Raise finding on a test, or add one manually in the Findings tab. Set the severity and write a recommendation.
  4. Verify physically. In Reconciliation enter the cash in hand, bank and wallet balances you actually counted. The system compares the total with the book balance and shows the variance.
  5. Management responds. The Treasurer or Admin replies to each finding. You can mark it resolved or accepted.
  6. Sign off. In Sign-off choose your opinion, write the conclusion and close the audit. The period is locked. Open Report to print or save it as PDF.

Audit trail

Audit trail lists every action with who, when and what changed (before and after values). Use the filters, export to CSV, and press Verify integrity to prove that no entry was altered or removed.

What the tests look for

Duplicate deposits, reused transaction IDs, entries made long after their date, amounts changed after posting, gaps in receipt numbers, expenses without bills, unusually large expenses, heads that spent more than collected, items waiting too long for approval, members without a valid phone number, and any tampering with the audit trail itself.

Signing in

Use the username and temporary password from the society office. At first sign-in you must choose your own password. Forgot it? Ask the office to reset it.

Deposit money

  1. Open Deposit money and read where to send the money (bKash, Nagad, Rocket or bank).
  2. Send the money from your phone or bank.
  3. Back on the page, enter the amount, the method, the transaction ID (TrxID) from your confirmation message, and the number you paid from. Press Submit for verification.
  4. The treasurer checks it. You get an SMS and a receipt when it is confirmed, or a message with the reason if it cannot be verified.

Where the society uses an online payment page instead, you only enter the amount and are taken to a secure page to pay.

See what I owe

The first page shows your expected contribution, what you have paid, and what is due for each contribution plan. “Pay full due” on the deposit page fills in the amount for you.

Receipts and notifications

My receipts lists every payment and lets you print a receipt. Notifications keeps a copy of every message the society sent you.

{% endif %} {# ------------------------------------------------------------------ #}

The SMS shows “Skipped”

Open the message to see the reason: the member's number is not a valid Bangladesh mobile number, the member turned SMS off, or SMS is switched off in Settings. Fix the cause; the deposit itself is not affected.

The SMS shows “Failed”

The SMS provider did not accept it. The Admin should check the provider details; then open the message and press Send / retry now, or use Send queued & retry failed in the Outbox.

Nothing is actually reaching phones

The system may still be in test mode (a yellow banner on the Message center says so). The Admin switches it to “HTTP provider” in Settings once the provider is configured.

“This date falls in an audited period which is locked”

An audit for that period has been signed off. Ask the Admin to re-open the audit if the change is genuinely needed.

My expense is not in the totals

It is probably still Pending. Only approved expenses count. Ask the Admin to approve it.

A member says they paid but nothing shows

Check Member payments for a pending request. If there is none, ask the member for the TrxID and record the deposit yourself.

“Transaction ID has already been submitted”

Each TrxID can be used once, to stop the same payment being counted twice. If the member entered it wrongly the first time, reject that payment and let them submit again.

Need a change to the system? Tell the person who looks after the software.
